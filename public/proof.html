02 / OBSERVED IBM BOB IDE WORK

Bob repaired the ordering, then earned the pass.

Bob used Cutover's read-only MCP tools in a reference-withheld workspace. Its first bidirectional-trigger idea failed through recursive triggers; that attempt remains in the task history. Bob then placed a one-way bridge before backfill and used explicit dual writes for the new worker.

The actual saved Parcel and Warehouse candidates were replayed independently against unchanged contracts. Each passed 116/116 bounded probes. Their window totals differ from the five-statement safe reference because Bob's plans have four migration statements.

03 / BOB-BUILT REVIEW GATE

Red, green, and red again—in real pull requests.

Bob's separate IDE task wrote the GitHub Actions review gate. It distinguishes a verified safety block from an unverified execution or audit error, and retains JSON, Markdown, ZIP, verdict, and job-summary evidence even when the check is red.

5–9 seconds per review job. In the three linked GitHub PR controls, jobs ran for 6 seconds (unsafe block), 9 seconds (safe pass), and 5 seconds (regression block), measured from job start to completion. That includes checkout, Python setup, the gate, and artifact upload. These are three synthetic runs, not a production speed guarantee.

What this evidence does—and does not—show.

The evaluator and browser were built by Codex before kickoff. Bob authored the event repair candidates and CI gate; the three PR controls use prewritten synthetic plans. A pass applies to these SQLite contracts and executed schedules. Cutover does not model concurrent transactions, locks, crashes, or production database behavior, and does not approve a deployment.
