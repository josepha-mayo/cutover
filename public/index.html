Coverage, constraints & Bob integration status ↗
This prototype executes 19 completed-rollout schedules for each input string, plus old updates and inserts at every boundary between SQLite migration statements. Two-write schedules rotate their second target across inputs, covering every ordered seed pair somewhere in a passing full suite without adding replays. Two bundled contracts use four strings each; an imported, validated single-table SQLite contract can supply 2–8. It does not simulate concurrent transactions, database locks, network failures, mid-statement interruption, every pair under every schedule and input, or a final column removal.
Imported SQL runs in a bounded disposable worker on this hosted demo and is not persisted by the application. The hosting service receives the request; run private schemas locally. IBM Bob integration is prepared through a local MCP server for bundled and imported contracts. The event-period Bob IDE repair and CI gate are documented with task summaries and independently replayed evidence in the public source. The reference plans and cross-record trap are prewritten examples; selecting one does not invoke an AI model.

For a table with an integer id and one text column, Cutover will build two candidate plans: a one-time backfill and a compatibility bridge. It validates the old contract, executes both against fresh databases, and compares the exact write that goes missing.
